Yes, you are correct. Algorithms like K-Means are called **"Parametric"** clustering methods because they require you to define the number of clusters ($k$) upfront.

However, there is an entire category of **"Non-parametric"** or **"Density-based"** clustering algorithms that determine the number of clusters automatically based on the structure of the data.

Here are the most common algorithms that do not require you to set $k$:

---

### 1. DBSCAN (Density-Based Spatial Clustering of Applications with Noise)
DBSCAN is one of the most popular alternatives to K-Means. Instead of looking for centers, it looks for areas of high density.
*   **How it works:** It groups together points that are close to many other points. If a point is in a "lonely" area, it is labeled as **noise** (outliers).
*   **The "K" factor:** You don't set $k$, but you do have to set `epsilon` (the maximum distance between two points to be considered neighbors) and `min_samples` (the minimum points needed to form a cluster).
*   **Best for:** Data with clusters of irregular shapes and data containing outliers.

### 2. HDBSCAN (Hierarchical DBSCAN)
This is a modern evolution of DBSCAN and is often considered the "gold standard" for clustering when you don't know $k$.
*   **How it works:** It performs DBSCAN over a varying range of distances and integrates the results to find the most "stable" clusters.
*   **The "K" factor:** It is much more robust than DBSCAN. You usually only need to set one parameter: `min_cluster_size`.
*   **Best for:** Real-world datasets where clusters have varying densities.

### 3. Mean Shift
Mean Shift is a "centroid-based" algorithm like K-Means, but it finds the centers automatically.
*   **How it works:** Imagine the data points are on a topographic map. Mean Shift pushes "centroids" uphill toward the areas of highest density (the peaks). Where these centroids converge becomes a cluster.
*   **The "K" factor:** You set a "bandwidth" (the radius of the area to search). The number of peaks found determines the number of clusters.
*   **Best for:** Image processing and computer vision.

### 4. Affinity Propagation
This algorithm works by having data points "vote" on which other points should be their "exemplars" (representatives).
*   **How it works:** Points send messages to each other until a set of high-quality representatives emerges. Each representative forms a cluster.
*   **The "K" factor:** The number of clusters is influenced by a "preference" parameter, but the algorithm decides the final count.
*   **Best for:** Problems where you want the "center" of the cluster to be an actual data point from the set.

### 5. Hierarchical Clustering (Agglomerative)
This creates a "tree" of clusters (a Dendrogram).
*   **How it works:** It starts by treating every single data point as its own cluster and then iteratively merges the two closest clusters until only one big cluster remains.
*   **The "K" factor:** You don't set $k$ to run it. However, after the tree is built, you "cut" the tree at a certain height to decide how many clusters you want.
*   **Best for:** Understanding the relationship between groups (e.g., taxonomy or gene sequences).

### Summary Table

| Algorithm | What you set instead of $k$ | Handles Outliers? | Best Use Case |
| :--- | :--- | :--- | :--- |
| **DBSCAN** | Distance (Epsilon) | Yes | Irregular shapes |
| **HDBSCAN** | Min Cluster Size | Yes | High-dimensional, messy data |
| **Mean Shift** | Bandwidth (Radius) | No | Finding "peaks" in density |
| **Affinity Prop.** | Preference/Damping | No | Small to medium datasets |
| **Hierarchical** | Tree Cut Height | No | Seeing sub-group relationships |

### Which one should you choose?
If you are looking for a "set it and forget it" replacement for K-Means, **HDBSCAN** is usually the best starting point. It handles noise well and requires the least amount of "guessing" regarding parameters.
